# 《杜甫全集》PDF 导入

本卷使用用户提供的 `杜甫全集.pdf`。PDF 内实际书名为《杜甫诗集》，杜甫著、钱谦益笺注、郝润华点校。全书 1,560 页，原文件不复制到网站公共目录。

- 来源 SHA-256：`08a7bb13a412aa6b727f44e1821e9a813d9f5c33940ff261d433bd0459d37736`。
- 网站目录：`docs/library/volume-94/`。
- 导入脚本：`scripts/import-du-fu.py`，依赖 PyMuPDF。
- 来源与生成稿清单：`scripts/du-fu-source-manifest.json`。
- 导航与统计：`docs/.vitepress/library.du-fu.mjs`。

## 拆分约定

按原书顺序，每一单篇诗作使用一篇 Markdown；具有共同总题的组诗使用同一篇 Markdown，保留组内各诗、注文和笺释的顺序。不同位置的同名作品不因标题相同而合并。

书签不是全部作品边界。诗歌补遗的三个书签按页内诗题拆为 45 个阅读页面；正文中附录的 16 篇他人唱酬诗也各自成页。《八哀诗》的总序及八篇具名诗合为一页；《江头五咏》保留五个子题。《九日五首》依原书保留“阙一首”，只录原有四首；补遗中的《李盐铁二首》和《绝句九首》保留原书关于其他篇已见前卷的说明，不重复补入前卷正文。

保留卷首五篇、二十卷、诗歌补遗和四类书后附录，共 1,224 个阅读页面。其中诗歌及组诗页面 1,167 个，其余为序跋、文赋、年谱和其他附录。原封面、上下册扉页图及旧目录不单独成页；各卷短说明放在本卷目录中。

本卷首页保存全部逐诗目录。侧栏只列各卷及附录入口，指向首页的稳定 `part-NN` 锚点，避免每篇网页重复嵌入一千多条逐诗链接；阅读页的 `prev`、`next` 元数据明确记录相邻篇目的地址，跨卷翻页不依赖侧栏。

## 文字与版式

全部 1,167 个诗歌及组诗页面在同一 Markdown 中提供“只读原文”和“原文与笺注”两个视图，默认显示纯原文。纯原文保留作者自序、诗句、作者署名及组内子题，去掉夹注、注号和注文；具名子题或编号提供同页目录。直接访问注释锚点时自动切换到笺注视图，纯原文视图不重复进入全文搜索。

去除夹注时不能仅凭字号：PDF 少数普通诗字误排成小字，部分“一作”“一云”等及音切又以正文大小排出。`PLAIN_RETAIN_SMALL`、`PLAIN_TEXT_REPLACEMENTS`、`PLAIN_PARAGRAPH_REPLACEMENTS` 与 `PLAIN_ANNOTATION_IMAGES` 记录对照来源处理的局部例外，只用于纯原文；笺注版仍与全部来源字符顺序一致。五、七言近体诗的各句字数另作检查，用于发现误删正文或残留夹注，不能据此擅改原书字词。

使用原生文字层，按基线合并被字体变化、上标及内嵌字形切开的行，连接跨页段落。诗歌按句末标点换行，散文及注文保持段落。

异文、音注及自注保留在原位置，用 `<small class="du-fu-variant">` 标示。原书的内嵌字形保留为本地图片；杜氏世系图作为独立图片保留。PDF 的 21 处失效字形本身显示为空框，保留实际字形裁片，不猜补文字。字形图片按来源物理宽高比随网页字号缩放。

原书 2,191 段有编号的注文均保留；2,189 处引用生成同页双向链接。每首组内重新起算的注号分别绑定自己的注文。三处原书有注文而正文缺少注号，保留注文，不凭空补号：

- PDF 第 681 页，《奉答岑参补阙见赠》〔一〕。
- PDF 第 745—746 页，《寄张十二山人彪三十韵》〔十一〕。
- PDF 第 816 页，《晚晴》〔一〕。

两处注号错位已查看原页确认，正文与注文各自保留原号，链接按所释词语对应，并在该篇显示简短校记：PDF 第 470—471 页《秋风二首》、第 974 页《玉台观》。正文中夹录他人诗作之后的编辑脚注，按实际引用移回对应作品，保持同页往返。

## 再生成与验证

```powershell
python -X utf8 scripts/import-du-fu.py <PDF路径>
python -X utf8 scripts/import-du-fu.py <PDF路径> --check
$env:VITEPRESS_BASE='/tolstoy/'
$env:NODE_OPTIONS='--max-old-space-size=12288'
npm run docs:build
```

脚本核对来源散列、完整来源行的分配、未解析注号及生成文件字节；另将生成正文去除排版标签，与所分配的来源文字按字符顺序比较，防止夹注、标题移动或段落拼接改变文字。`--check` 只验证，不改动文件。生成的 Markdown 固定使用 LF 换行。仅在旧清单散列匹配时，正常导入才清理不再使用的旧生成文件。普通网站构建使用仓库中的 Markdown 和图片，无须访问原 PDF 或运行 Python。

内容核查采用来源文字覆盖检查、篇目与组诗边界检查，以及对选定原页和网页的实际抽查；这些检查不表示已对全书 1,560 页完成逐字人工校勘。
